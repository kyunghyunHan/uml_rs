# UML Studio

Rust + egui/eframe 기반 UML 데스크톱 편집기입니다. 한 프로젝트에 유스케이스·시퀀스·클래스 다이어그램을 자유롭게 추가하고 `.umlproj`로 저장하며 PNG/SVG로 내보냅니다. 권장 탐색 순서는 유스케이스 → 시퀀스 → 클래스이며 작성 순서를 강제하지 않습니다.

이번 개선은 로컬 `c5d5836`에서 시작했습니다. 원격 조회와 네이티브 GUI 실행이 승인되지 않아 원격 최신 상태 및 이번 개선본의 실제 창 실행은 확인하지 못했습니다. 모델 기반 PNG를 직접 확인했고, 실제 egui 위젯을 창 없이 렌더링한 일반/작은 화면 이미지도 확인했습니다. Windows/Linux 실행, OS 파일 대화상자와 한국어 IME 조합 입력은 미검증입니다.

## 실행과 예제

Rust 1.88 이상과 플랫폼 개발 도구가 필요합니다. macOS는 Xcode Command Line Tools, Linux는 OpenGL·X11/Wayland·xkbcommon 개발 라이브러리 및 파일 대화상자용 XDG Desktop Portal이 필요합니다. 플랫폼별 설치 패키지는 배포 환경에 맞게 준비하세요.

```sh
cargo run
cargo build --release
```

시작 화면의 기본 예제 또는 [sorting.umlproj](examples/sorting.umlproj)를 사용하세요. 이전 v1 파일도 열 수 있습니다. [개선 검증 예제](examples/review.umlproj)는 여러 크기의 액터, 긴 한글 클래스/메서드, 노트, 중첩 활성 구간, 범위가 있는 alt/loop, 생성·소멸과 다이어그램 간 연결을 포함합니다.

[예제 유스케이스 PNG](examples/review-exports/diagram-1.png) · [클래스 PNG](examples/review-exports/diagram-2.png) · [시퀀스 PNG](examples/review-exports/diagram-3.png). 같은 폴더에 글자를 경로로 변환한 SVG도 있습니다.

## 편집 화면

- 상단 공통 작업에서 파일, 실행 취소/다시 실행, 내보내기를 사용합니다. **보기** 메뉴에서 프로젝트·속성·진단 패널을 접거나 펼칩니다. 폭 1,000 미만으로 처음 줄이면 두 사이드 패널을 접어 캔버스를 확보합니다. 직접 다시 펼칠 수 있습니다.
- 왼쪽에서 프로젝트/다이어그램과 요소를 검색합니다. 다이어그램 행의 우클릭 메뉴에서 이름 변경·복제·삭제를 실행합니다. 이름 필드로도 변경할 수 있습니다. 목록에서 도형을 선택하면 그 위치로 화면을 이동합니다.
- 다이어그램을 열면 가로 스크롤 가능한 탭에 추가됩니다. 탭의 **닫기**는 탭만 닫습니다. 다이어그램 삭제는 목록의 명시적인 문맥 메뉴에 있습니다. 삭제와 복제는 실행 취소할 수 있습니다.
- **요소 추가** 팔레트는 도형 아이콘과 이름을 함께 표시합니다. 도구를 선택하고 캔버스를 클릭하세요. **관계 연결**에서 종류를 고른 뒤 시작 → 도착 순서로 클릭하거나 시작 도형에서 도착 도형으로 드래그합니다. 액터는 선 사이의 빈 공간을 포함한 선택 상자 안에서 클릭할 수 있습니다. 기존 관계선/라벨이 겹쳐도 연결 대상 도형을 찾습니다. 연결 중 종류·단계 안내와 유효/불가능 대상 미리보기가 나타납니다. 잘못된 연결은 이유를 상태 메시지로 알리고 시작점을 유지하므로 다른 도착 대상을 선택할 수 있습니다. 시작점을 바꾸려면 **연결 취소** 또는 **Esc**를 누르고 관계 도구를 다시 선택하세요.
- 오른쪽 속성은 선택 종류에 맞게 표시하며 좌표와 크기는 **외형 · 배치**에 접어 둡니다. 도형/참여자/메시지를 더블클릭하면 이름 편집 필드로 이동합니다. 다중 선택에는 개별 의미 속성을 표시하지 않습니다.
- 진단이 있으면 하단 목록에서 원인과 대상을 확인하고 클릭해 해당 다이어그램/속성을 열 수 있습니다. 구조를 읽을 수 있는 기존 파일의 잘못된 관계는 삭제하지 않고 수정할 수 있도록 유지합니다.

### 캔버스와 단축키

클릭으로 선택하고 Shift 또는 Cmd/Ctrl+클릭으로 다중 선택합니다. 빈 공간 드래그로 범위를 선택합니다. Alt+클릭은 겹친 도형/관계의 선택을 순환합니다. 도형을 드래그해 이동하고 우하단 핸들로 크기를 바꿉니다. 시퀀스 참여자/메시지 순서는 왼쪽 목록의 행을 드래그하거나 기존 속성 패널의 순서 버튼으로 변경합니다.

휠/트랙패드 스크롤, Space+드래그, 가운데/오른쪽 버튼 드래그로 화면을 이동합니다. Cmd/Ctrl+휠 또는 핀치로 포인터 기준 확대/축소를 합니다. 확대 선택 메뉴에서 비율이나 100%를 선택할 수 있습니다. 우클릭 문맥 메뉴의 복사/붙여넣기/복제/삭제는 오른쪽 드래그 이동과 구분됩니다.

**더보기**에서 노드 정렬, 가로/세로 중앙선 맞춤, 균등 간격과 선택 영역 맞춤을 사용합니다. 노드 정렬과 연결선의 직선 경로 설정은 별도입니다. 그리드와 맞춤은 독립적으로 켭니다. 클래스 관계의 끝 원을 드래그하면 테두리에 붙어 이동하며, 맞춤을 켜면 가까운 연결점의 X/Y와 중앙에 스냅합니다.

| 단축키 | 기능 |
|---|---|
| Cmd/Ctrl+N / O | 새 프로젝트 / 열기 |
| Cmd/Ctrl+S / Shift+Cmd/Ctrl+S | 저장 / 다른 이름으로 저장 |
| Cmd/Ctrl+Z | 실행 취소 |
| Shift+Cmd/Ctrl+Z 또는 Cmd/Ctrl+Y | 다시 실행 |
| Cmd/Ctrl+A | 현재 다이어그램 전체 요소 선택 |
| Cmd/Ctrl+C / V / D | 복사 / 붙여넣기 / 복제 |
| Delete / Backspace | 선택 삭제 |
| Space+드래그 | 화면 이동 |
| F / Esc | 전체 화면 맞춤 / 연결·도구 취소 |

텍스트 필드에 포커스가 있으면 캔버스 단축키를 적용하지 않습니다. 드래그 한 번과 연속 텍스트 입력을 편집 이력으로 묶으며 최대 100개를 유지합니다. 화면 이동/확대는 이력에서 제외합니다. 클립보드는 앱 내부용입니다.

### 관계와 경로

생성·속성 변경·진단·저장이 모델 계층의 같은 UML 규칙을 사용합니다. 잘못된 대상 변경은 프로젝트에 적용하지 않고 속성 패널에 이유와 수정 초안을 유지합니다. 양쪽 대상을 차례로 수정해 유효하게 만들거나 **관계 수정 취소**를 선택할 수 있습니다.

- 일반화/구현의 도착은 상위 요소/인터페이스입니다. 클래스 계층 및 인터페이스 간 일반화를 허용하고 자기 상속과 일반화 순환을 거부합니다. 구현은 클래스/추상 클래스 → 인터페이스 방향입니다.
- 클래스의 자기 연관은 허용합니다. 집합/합성의 시작이 전체이며 해당 끝에 빈/채운 마름모를 표시합니다.
- 유스케이스 연관은 액터↔유스케이스, include는 포함하는 유스케이스→포함 대상, extend는 확장 유스케이스→기본 대상입니다. 액터끼리/유스케이스끼리 일반화할 수 있습니다.
- 일반 연관은 화살표 없는 실선입니다. 생성 메뉴에서 일반 연관과 시작→도착 / 도착→시작 / 양방향을 구분하고 각 관계의 표기를 미리 보여줍니다.
- 연관·집합·합성은 시작/도착 각각 미지정(표시 없음), 탐색 가능(열린 화살표), 탐색 불가(x)를 설정합니다. 다이아몬드는 탐색 상태와 독립적으로 전체 쪽에 유지됩니다. 유스케이스의 기본 연관은 그대로입니다.
- 시작↔도착 교환은 역할·다중성·탐색 상태·연결점과 수동 경로 순서도 함께 바꿉니다. UML 규칙에 어긋나는 교환은 수정 초안과 오류로 안내합니다.
- 역할·다중성·관계 이름을 편집합니다. 다중성 프리셋과 숫자·범위 검증을 제공하며 합성의 전체 쪽 상한이 1을 넘으면 진단합니다. 노트 연결은 점선이며 화살촉이 없습니다.

관계 속성 또는 관계 우클릭 메뉴에서 **자동 / 직선 / 직교** 경로를 고릅니다. 자동은 직접 연결할 수 있으면 직선을 쓰고, 장애물이 있으면 직교 후보와 가시성 격자를 탐색합니다. 직선은 장애물을 우회하지 않으며, 직교는 수평·수직 선분만 사용합니다. 같은 축으로 바로 연결할 수 있으면 직교도 한 선분으로 표시합니다. 자기 연결은 직선 모드에서도 루프입니다.

선택한 관계의 파란 조절점을 드래그하거나 **경로 조절점**에서 점을 편집합니다. `bend`와 `waypoints`는 모드를 바꿔도 우선 유지합니다. **자동 경로 초기화**로 수동 점을 제거한 뒤 다시 계산할 수 있습니다. 위/아래/왼쪽/오른쪽 중앙 연결점을 지정하거나 양 끝의 원을 드래그할 수 있으며 노드 이동·크기 변경 후에도 테두리에 붙습니다. 경로가 요소 안을 지나면 속성 패널에 안내합니다.

### 클래스·노트·패키지

클래스·인터페이스·추상 클래스 및 기본 열거형 상자를 지원합니다. 접근 제어자, 타입, 기본값, 메서드 매개변수/반환 타입, static/abstract를 편집하고 순서를 바꿉니다. static은 밑줄, abstract는 기울임으로 표시합니다.

새 클래스는 **자동 크기**입니다. 이름과 멤버 텍스트를 수정하면 폰트 측정 결과에 따라 커집니다. 크기 핸들/크기 필드를 사용하면 **수동 크기**로 바뀝니다. 수동 모드는 폭에 맞춰 줄을 나누고 높이가 부족하면 속성 패널에 안내합니다. 사용자 크기를 자동으로 덮어쓰지 않으며 **내용에 크기 맞춤**을 별도로 사용할 수 있습니다. **빈 속성·메서드 구획 숨김** 옵션을 지원합니다.

속성/메서드 섹션의 **빠른 추가**에는 `- policy: SortPolicy`, `+ sort(values: List<int>): void`를 입력합니다. 접근 제어자 뒤 `static`, `abstract`도 사용할 수 있습니다. 불완전한 입력은 해당 필드 근처에서 설명합니다. 기존 개별 필드 편집도 유지합니다.

노트는 여러 줄 주석과 점선 연결을 지원합니다. 패키지는 이름 있는 포함 경계입니다. 기본 열거형은 멤버 편집 구조를 재사용하며 전용 리터럴 편집기나 전체 UML 패키지 의미 모델은 제공하지 않습니다.

### 유스케이스 명세와 경계

유스케이스 이름과 별개로 목표·설명·주요 액터·사전조건·기본 흐름·대안/예외·사후조건을 작성합니다. **관련 시퀀스**를 선택해 ID로 연결하고 **열기**로 이동합니다.

경계/패키지의 포함 관계는 `boundary` ID로 관리합니다. 새 도형은 생성 위치를 포함하는 가장 작은 경계에 배정하고 속성 패널에서 소속을 바꾸거나 해제합니다. 경계가 겹치거나 크기가 바뀌어도 기존 소속을 재추론하지 않습니다. 경계를 이동하면 명시적 자식이 함께 이동하며, 복사하면 자식과 내부 관계도 복사합니다. 경계 삭제 시 자식은 유지하고 소속을 해제합니다.

### 시퀀스·활성 구간·프래그먼트

**시퀀스 추가**에서 참여자·메시지·활성 구간·프래그먼트를 만드세요. 두 참여자를 Shift+선택하면 **선택 참여자로 메시지**를 사용할 수 있습니다. 선택된 두 참여자의 현재 좌우 순서를 발신→수신으로 사용하며 속성에서 바꿀 수 있습니다.

동기·비동기·반환·생성·소멸 및 자기 호출을 지원합니다. 생성 메시지의 수신자 헤더/생명선은 해당 이벤트에서 시작하고 소멸 이벤트는 생명선을 끝내며 X를 그립니다. 생성 전/소멸 후 메시지와 중복 생성은 진단합니다. 참여자 ID마다 하나의 생명주기를 표현하며 소멸한 객체를 다시 생성하려면 새 참여자를 추가합니다. 메시지 라벨은 실제 폰트 폭과 가용 간격으로 줄을 나누고 필요한 행/참여자 간격을 확보합니다.

활성 구간은 참여자와 시작/종료 이벤트 ID를 지정합니다. 겹치는 구간은 별도 가로 레인에 배치하며 좌우 메시지와 자기 호출/반환은 해당 활성 막대 가장자리에 연결합니다. **활성 구간 자동 생성**은 선택 옵션이며 동기 호출과 반환을 짝지어 생성합니다. 자동 구간을 수동으로 전환하거나 원래 수동 구간을 계속 편집할 수 있습니다.

alt/opt/loop에 조건·이벤트 범위·참여자 범위를 지정합니다. alt는 else 조건과 분기 시작 이벤트를 편집하며 분기 구분선과 조건을 위한 공간을 메시지 사이에 확보합니다. 중첩 범위는 단계별 여백을 사용합니다. 범위 변경은 메시지 순서를 바꾸지 않습니다. 선택이 겹치면 Alt+클릭이나 요소 목록을 사용하세요.

이벤트 삭제 시 범위 끝점은 이웃 이벤트로 옮기고, 메시지가 모두 없어지면 관련 구간을 제거합니다. 참여자 삭제 시 관련 메시지와 무효한 구간을 제거하며 실행 취소로 복원할 수 있습니다. 복사 시 필요한 참여자·메시지·구간·프래그먼트와 내부 참조의 ID를 다시 발급합니다.

### 다이어그램 사이의 연결

참여자의 타입 선택에서 같은 프로젝트의 클래스·인터페이스·열거형을 선택합니다. 메시지에는 수신 타입의 메서드를 선택적으로 연결합니다. 타입/메서드를 선택하지 않는 자유 참여자와 자유 메시지도 지원합니다. 연결 이름은 원본 변경을 반영하며 연결된 이름을 직접 편집하려면 먼저 연결을 해제합니다.

같은 이름으로 동일 객체를 추정하지 않습니다. `type_ref`, `method_ref`, 명세의 시퀀스 ID를 사용합니다. 삭제된 대상이나 수신 타입과 맞지 않는 메서드는 진단하며 선택 메뉴에서 해제하거나 다시 연결할 수 있습니다. 동일 프로젝트 내 복사는 외부 타입/메서드 연결을 유지합니다. 다른 프로젝트에 붙여넣어 참조 대상이 없으면 진단을 보고 다시 지정하세요.

## 저장·마이그레이션·복구

현재 형식은 UTF-8 JSON `format_version: 3`입니다. v1/v2를 열 때 ID·관계·위치·크기를 유지하고 추가 필드에 기본값을 적용합니다. v1 클래스 크기는 수동으로 유지하며 기존 중심점 기반 경계 소속은 가장 작은 경계 ID로 한 번 변환합니다. 원본 파일은 저장 전까지 변경하지 않습니다. 기존 `navigable=true`는 도착 끝 탐색 가능, `false`는 양 끝 미지정으로 변환합니다. 새 저장에는 양 끝 탐색 상태, 경로 모드와 테두리 연결점을 기록합니다. v3를 v1/v2 앱에서 여는 하위 호환은 제공하지 않습니다.

설계 의미와 `layout`/`waypoints`/`view`를 분리한 필드로 저장합니다. 다이어그램별 이동/확대, 명세, 포함 관계, 크기 모드, 생성·소멸, 범위와 다이어그램 간 참조를 저장합니다. 선택/도구/속성 초안/egui 상태/이력은 저장하지 않습니다.

중복 ID·잘못된 좌표·구조적으로 깨진 이벤트 참조·잘못된 JSON·미지원 버전은 오류를 표시합니다. 구조를 읽을 수 있는 의미 오류는 로드 후 진단하며 정상 저장 전에 수정해야 합니다. 복구 저장은 의미 오류가 있는 수정 내용도 보존합니다. 정상 저장과 복구 모두 같은 폴더의 임시 파일에 쓰고 동기화한 뒤 이름을 바꿉니다. 읽기/쓰기 제한은 32 MiB입니다.

변경 표시 `•`가 있으면 저장이 필요합니다. 창 닫기/프로젝트 교체 시 저장·버리기·취소를 선택합니다. 20초마다 별도 복구 사본을 만들고 시작 화면에서 복구할 수 있습니다. 정상 저장하면 복구 사본을 제거합니다. 최근 목록과 단일 복구 파일의 기본 위치는 `$HOME/.uml-studio`이며 `UML_STUDIO_HOME`으로 바꿉니다. HOME이 없으면 임시 폴더를 사용합니다. 여러 앱 인스턴스는 서로 다른 복구 폴더를 사용하세요.

## PNG/SVG 내보내기

**내보내기**에서 PNG/SVG, 1x/2x/3x, 여백, 흰색/투명 배경을 선택합니다. 미리보기와 예상 픽셀 크기를 표시합니다. 공통 장면을 사용하며 화면 밖 요소도 모두 포함합니다. 확대/이동·UI 테마와 무관하고 그리드·선택·조절점·가이드는 출력하지 않습니다.

투명 배경에서는 바깥 배경과 경계 내부가 투명하며 클래스·유스케이스·활성 막대·노트 등 UML 도형의 내부는 흰색입니다. 포함된 한글 폰트로 PNG를 렌더링하며 SVG 파일은 텍스트를 경로로 변환해 폰트 설치에 의존하지 않습니다. 빈 다이어그램, 한 변 16,384px 또는 4천만 픽셀 초과 출력은 오류로 알립니다. 수동 크기에서 넘친 텍스트도 전체 출력 경계에 포함됩니다.

```sh
cargo run -- --example examples/sorting.umlproj
cargo run -- --review-example examples/review.umlproj
cargo run -- --export examples/review.umlproj /tmp/uml-output
cargo run -- --export-svg examples/review.umlproj /tmp/uml-output
```

CLI 기본값은 2x, 여백 32, 흰색이며 `diagram-1.png`/`diagram-1.svg`처럼 저장합니다. 기존 `--export` 명령은 유지합니다.

## 검증과 UI 이미지

```sh
cargo fmt --check
cargo check
cargo test
cargo clippy --all-targets
# 네이티브 실행이 가능한 환경에서만 사용
cargo run --example gui_smoke -- /tmp/uml-native.png 1 --review
# 창 없이 실제 egui UI를 CPU로 렌더링
cargo run --example ui_snapshot -- /tmp/uml-ui.png 1
cargo run --example ui_snapshot -- /tmp/uml-small.png 0 --small
```

테스트는 관계 생성/수정 공통 검증과 상속 순환, 액터 좌표, 자동/수동 클래스, 중첩 활성/프래그먼트, 생성/소멸, 타입/메서드 참조, v1 마이그레이션, 복사/이력과 PNG/SVG를 검증합니다. 유스케이스·클래스의 지원 관계 19개 조합을 클릭·드래그로 생성하고, 확대/이동 상태의 대상 판정, 선과 액터의 겹침, 잘못된 대상과 재시도, 도구 전환·취소, 자기 연관, 관계 수정·이력·저장 왕복을 검사합니다. 실제 앱의 관계 메뉴 선택부터 캔버스 연결·실행 취소/다시 실행까지도 egui 이벤트로 실행합니다. 캔버스 확대 후 이동/크기 변경, 관계 조절점 드래그와 시퀀스 행 드래그도 포인터 이벤트로 검증합니다.

UI 이미지는 OS 창 캡처가 아닌 **headless egui 렌더링**입니다. 배치와 표시 내용 검증용 CPU 렌더러이므로 GPU 출력의 안티앨리어싱과 차이가 있을 수 있습니다. 다이어그램 PNG 내보내기와는 별도입니다.

## 구조

- `model.rs`, `validation.rs`, `references.rs`: 데이터, UML 규칙, ID 연결/진단과 이름 반영
- `text_layout.rs`, `sequence_layout.rs`, `routing.rs`: 폰트 측정/줄바꿈, 이벤트·활성·프래그먼트, 직교 경로/연결점
- `scene.rs`, `export.rs`: 공통 렌더링 장면, 화면 표시, 미리보기/PNG/SVG
- `canvas.rs`, `commands.rs`: 입력·선택·편집 명령·이력·복사/붙여넣기
- `properties.rs`, `palette.rs`, `app.rs`: 종류별 속성 UI, 팔레트, 앱/파일/프로젝트 흐름
- `storage.rs`, `migration.rs`: 원자적 저장, 복구, 버전 변환
- `demo.rs`, `tests/`: 개선 예제와 회귀 검증

## 남은 제한

- 자동 라우팅은 직교 후보와 가시성 격자를 사용하며 대규모 격자는 40,000점으로 제한합니다. 겹친 노드나 극도로 밀집한 그래프에서는 교차 없는 경로/라벨 배치를 보장하지 않습니다. 연결점·조절점 또는 노드 배치를 조정하세요.
- 활성 구간 자동 생성은 동기 호출/반환의 단순 짝짓기입니다. 예외·동시 실행·스레드 의미를 추론하지 않습니다. 시간상 겹치는 구간에 레인을 배정하며 부분적으로 교차하는 프래그먼트를 올바른 중첩 구조로 재작성하지 않습니다. alt는 두 분기입니다.
- 참여자/메시지 드래그 순서 변경은 왼쪽 목록에서 제공합니다. 캔버스에서 메시지 재정렬하거나 자유 좌표로 이동하는 기능은 없습니다.
- SVG 글자는 이식 가능한 경로로 변환되므로 SVG 텍스트 객체로 직접 수정할 수 없습니다. 수동 클래스 높이가 부족하면 줄바꿈된 내용이 상자 아래로 넘칠 수 있으며 경고와 크기 맞춤을 사용해야 합니다.
- 열거형은 기본 상자/멤버 편집, 패키지는 포함 경계 범위입니다. UML의 모든 의미 제약이나 상속된 메서드 목록 탐색을 제공하지 않습니다.
- 이번 개선본의 네이티브 창 실행, 파일 대화상자, IME 입력, Windows/Linux 실행, 설치 패키지와 macOS 서명/공증은 미검증 또는 미제공입니다.
- 클라우드/협업, AI 설계 생성, 코드 생성/역공학과 타 UML 도구 파일 가져오기는 범위 밖입니다.

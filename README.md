# UML Studio

Rust + egui/eframe 기반 UML 데스크톱 편집기입니다. 한 프로젝트에서 클래스, 유스케이스, 시퀀스 다이어그램을 여러 개 만들고 편집하고 저장합니다. macOS 네이티브 실행과 화면 렌더링을 확인했습니다. Windows/Linux용 플랫폼 의존성도 구성했으나 해당 OS의 빌드와 실행은 검증하지 않았습니다.

## 실행

Rust 1.88 이상과 플랫폼 개발 도구가 필요합니다. macOS에서는 Xcode Command Line Tools를 설치하세요.

```sh
cargo run
# 배포용 실행 파일: target/release/uml-studio
cargo build --release
```

Linux에서는 C/C++ 빌드 도구, OpenGL, X11/Wayland, xkbcommon 개발 라이브러리와 파일 대화상자용 XDG Desktop Portal이 필요합니다. 예: Debian/Ubuntu의 `build-essential libgl1-mesa-dev libxkbcommon-dev libwayland-dev libx11-dev libxcursor-dev libxi-dev libxrandr-dev libxinerama-dev libx11-xcb-dev xdg-desktop-portal`.

시작 화면에서 새 프로젝트를 만들거나 `.umlproj` 파일을 여세요. ‘정렬 프로그램’ 예제 열기 버튼 또는 [examples/sorting.umlproj](examples/sorting.umlproj)를 사용해 세 종류를 확인할 수 있습니다. 예제에는 사용자 → SortService → BubbleSort 실행 흐름과 SortPolicy 인터페이스가 함께 들어 있습니다.

## 조작

- 왼쪽 목록에서 다이어그램을 열면 탭이 추가됩니다. `+ 추가`에서 종류를 자유롭게 선택하고, 이름 필드에서 이름을 바꿉니다. 목록의 `×`는 다이어그램 삭제이며 실행 취소할 수 있습니다. 탭의 `×`는 탭만 닫습니다.
- 클래스/유스케이스는 상단 도구를 고르고 캔버스를 클릭해 추가합니다. 관계 도구를 고른 뒤 시작 요소, 도착 요소 순서로 클릭합니다. Esc로 취소합니다.
- 요소/선을 클릭해 선택합니다. Shift 또는 Cmd/Ctrl+클릭으로 다중 선택하고 빈 공간을 드래그해 범위 선택합니다. 클래스/유스케이스 요소는 드래그로 이동하고 우하단 핸들로 크기를 바꿉니다.
- 시스템 경계를 이동하면 중심점이 경계 안에 있는 유스케이스가 함께 이동합니다. 클래스 멤버를 추가/삭제하면 기본 크기를 다시 계산하며 ‘내용에 크기 맞춤’도 사용할 수 있습니다.
- 마우스 휠/트랙패드 스크롤 또는 가운데/오른쪽 버튼 드래그로 화면을 이동합니다. Cmd/Ctrl+휠 또는 핀치로 마우스 위치를 기준으로 확대합니다. `F` 또는 ‘화면 맞춤’으로 전체를 봅니다.
- ‘선택 편집’ 메뉴에서 삭제, 복사, 붙여넣기, 복제, 여섯 방향 정렬을 사용할 수 있습니다. 오른쪽 속성 패널에서 이름, 클래스 멤버, 선 라벨, 역할, 다중성, 탐색 방향, 직교 경로의 중간 축 좌표를 편집합니다.
- 클래스 멤버의 접근 제어자, 타입, 기본값, 매개변수/반환 타입, static/abstract를 편집할 수 있습니다. static은 밑줄, abstract는 기울임으로 표시합니다. 속성/메서드 목록의 ↑/↓로 순서를 바꿉니다.
- 일반화/구현의 **도착**은 상위 요소/인터페이스입니다. 집합/합성의 **시작**은 전체이며 마름모가 그쪽에 표시됩니다. include는 포함 대상, extend는 기본 유스케이스를 도착으로 선택합니다.

| 단축키 | 기능 |
|---|---|
| Cmd/Ctrl+N / O | 새 프로젝트 / 열기 |
| Cmd/Ctrl+S / Shift+Cmd/Ctrl+S | 저장 / 다른 이름으로 저장 |
| Cmd/Ctrl+Z | 실행 취소 |
| Shift+Cmd/Ctrl+Z 또는 Cmd/Ctrl+Y | 다시 실행 |
| Cmd/Ctrl+A | 현재 다이어그램의 전체 요소 선택 |
| Cmd/Ctrl+C / V / D | 복사 / 붙여넣기 / 복제 |
| Delete / Backspace | 선택 삭제 |
| F / Esc | 화면 맞춤 / 도구 취소 |

텍스트 필드에 포커스가 있으면 캔버스 단축키를 적용하지 않습니다. 복사 내용은 앱 내부 클립보드에 저장합니다. 실행 취소 이력은 최대 100개이며 드래그 한 번, 연속 텍스트 입력을 묶습니다. 화면 이동/확대는 편집 이력에 넣지 않습니다.

### 시퀀스

시퀀스는 참여자 순서와 메시지 이벤트 순서로 배치합니다. 참여자를 추가한 다음 메시지를 추가하고 오른쪽에서 발신자/수신자/종류/내용을 설정하세요. 발신자와 수신자가 같으면 자기 호출이 됩니다. 참여자는 속성 패널의 좌우 버튼으로, 메시지는 위아래 버튼으로 순서를 바꿉니다. 선택 메시지 위/아래에 삽입할 수도 있습니다. 캔버스에서 자유 좌표로 옮기는 대신 이 순서 편집을 사용합니다.

활성 구간은 참여자와 시작/종료 이벤트를 지정합니다. alt/opt/loop 프래그먼트에는 조건과 시작/종료 이벤트를 지정하고, alt의 else 조건과 분기 이벤트도 편집할 수 있습니다. 이벤트 삭제 시 범위 끝점은 이웃 이벤트로 옮기며, 메시지가 모두 없어지면 관련 구간/프래그먼트를 제거합니다. 참여자를 지우면 관련 메시지와 무효한 구간도 제거합니다. 실행 취소로 복원할 수 있습니다.

시퀀스 복사는 필요한 참여자와 메시지, 유효한 활성 구간/프래그먼트를 함께 복제하고 모든 ID를 재발급합니다. 선택한 메시지의 발신자/수신자도 복제됩니다.

## 저장과 복구

`.umlproj`는 UTF-8 JSON입니다. `format_version: 1`, 프로젝트/다이어그램/요소/멤버/관계/이벤트의 UUID, 다이어그램 종류, 설계 정보, `layout`(월드 위치/크기), `bend`(직교 경로), `view`(이동/확대)를 저장합니다. 시퀀스의 배열 순서가 참여자/이벤트 순서이며 활성 구간/프래그먼트는 이벤트 ID를 참조합니다. 선택 상태, 도구, egui UI 상태와 실행 취소 이력은 저장하지 않습니다.

저장 전에 버전, 좌표, ID 중복과 참조를 검사합니다. 같은 디렉터리의 임시 파일에 쓰고 동기화한 뒤 이름을 바꿔 기존 파일을 교체합니다. 지원하지 않는 버전, 잘못된 JSON과 저장 실패는 오류 창으로 알립니다. 읽기 제한은 32 MiB입니다.

변경 표시 `•`가 있으면 저장이 필요합니다. 창 닫기와 프로젝트 교체 시 저장/버리기/취소를 선택합니다. 변경이 있는 동안 20초마다 정상 저장과 별개인 복구 사본을 만듭니다. 시작 화면에서 복구할 수 있으며 복구 후에는 저장할 파일을 선택해야 합니다. 정상 저장하면 복구 사본을 제거합니다.

최근 프로젝트 목록과 단일 복구 파일은 기본적으로 `$HOME/.uml-studio`에 있습니다. `UML_STUDIO_HOME`으로 폴더를 바꿀 수 있습니다. HOME이 없는 환경에서는 임시 폴더를 사용합니다. 여러 앱 인스턴스가 같은 복구 폴더를 공유하면 복구 파일이 덮어써질 수 있으므로 인스턴스별 폴더를 사용하세요.

## PNG 내보내기

‘PNG 내보내기’에서 1x/2x/3x, 여백, 흰색/투명 배경을 고르고 저장합니다. 월드 좌표의 공통 렌더링 장면을 SVG로 변환한 후 resvg로 래스터화합니다. 화면 캡처를 사용하지 않으며 현재 확대/이동과 무관하게 화면 밖 요소, 텍스트와 화살표까지 포함합니다. 그리드/선택 표시/핸들은 출력하지 않습니다. 한글 폰트는 실행 파일에 포함됩니다. 빈 다이어그램 및 한 변 16,384px 또는 총 4천만 픽셀을 넘는 출력은 오류를 표시합니다.

GUI 없이 예제 생성과 전체 다이어그램 PNG 출력도 가능합니다.

```sh
cargo run -- --example examples/sorting.umlproj
cargo run -- --export examples/sorting.umlproj /tmp/uml-output
```

생성된 예제 PNG는 [examples/exports](examples/exports)에 포함되어 있습니다. 출력 파일 이름은 `diagram-1.png`, `diagram-2.png`, …입니다. CLI 출력 기본값은 2x, 흰색 배경, 여백 32입니다.

## 구조와 검증

- `src/model.rs`: 의미 모델, 배치 데이터, 시퀀스 참조 정리/유효성 검사
- `src/commands.rs`: 편집 명령, 복사/붙여넣기, 실행 취소/다시 실행
- `src/canvas.rs`: 선택/드래그/확대, 좌표 변환
- `src/scene.rs`: 공통 도형 장면, 관계 경로/히트 테스트, 화면 및 SVG/PNG 렌더링
- `src/storage.rs`: 파일 교체 저장, 최근 목록, 복구 경로
- `src/app.rs`: 앱 상태, 시작 화면, 파일 흐름, 편집 UI
- `tests/workflows.rs`: 저장 왕복, 참조와 ID, 이력, 시퀀스, 캔버스 입력, 한글/PNG 검증

```sh
cargo fmt --check
cargo check
cargo test
cargo clippy --all-targets
# macOS에서 실제 창을 띄워 렌더링 확인 후 자동 종료 (0 유스케이스, 1 클래스, 2 시퀀스)
cargo run --example gui_smoke -- /tmp/uml-gui.png 1
```

GUI smoke의 스크린샷은 UI 검증용이며 다이어그램 PNG 내보내기와 별도입니다. macOS에서 세 화면을 실행하고 한글과 화살표 배치를 확인했습니다. 자동 검증에는 실제 포인터 이벤트를 전달한 확대 후 이동/크기 조절도 포함됩니다. OS 파일 대화상자 조작과 한국어 IME 조합 입력을 자동화한 검증은 포함하지 않습니다.

## 알려진 제한

- 직교 연결은 중간 축 하나를 속성에서 수동 조절합니다. 장애물 회피, 여러 중간점, 포트 편집과 자동 라벨 충돌 회피는 없습니다. 요소를 겹치거나 라벨을 길게 입력하면 수동 배치가 필요합니다.
- 시퀀스 활성 구간은 참여자 중앙에 표시하며 중첩 호출 깊이별 가로 오프셋을 자동 추론하지 않습니다. alt는 두 분기만 지원하고 복잡한 중첩 프래그먼트의 충돌은 자동 정리하지 않습니다.
- 시퀀스 메시지 라벨은 32자 단위로 줄을 나눕니다. 매우 긴 조건/참여자 이름은 그림 폭을 늘릴 수 있습니다.
- Windows/Linux 실행, 설치 패키지, macOS 코드 서명/공증은 제공하지 않습니다. 현재 산출물은 Cargo 프로젝트와 네이티브 개발 빌드입니다.
- AI 생성, 코드 생성/역공학, 협업/클라우드와 타 UML 도구 파일 가져오기는 범위에 포함하지 않습니다.
